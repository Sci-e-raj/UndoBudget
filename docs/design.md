# UndoBudget: implemented design and current limits

This is the CSL3030 **irreversibility budget for process groups** project in
this repository's xv6-riscv tree. A group shares one bounded allowance for
selected irreversible operations. The kernel refuses an operation before its
effect in FAIL mode, or waits for refill in BLOCK mode. The numerical policy
below was chosen for this project; the figures in `xv6_projects.pdf` were
illustrations, not an assigned cost table. This document distinguishes the
approved policy from kernel enforcement that exists today.

## Architecture and syscall flow

`kernel/main.c` calls `groupinit()` before user processes start. There are
`NGROUP=16` permanent slots in `kernel/group.c`, each with its own spinlock,
configuration, balance, refill timestamp, and counters. `struct proc` has one
`gid` and no private balance. `kfork()` copies the parent's gid before making
the child runnable. `kexec()` changes the process image but does not change
gid. Exit, reparenting, and shell restart never allocate a fresh group or reset
its balance; configured slots last until reboot.

| User call | Kernel path | Current result |
| --- | --- | --- |
| `hello(a,b,c,d)` | stub → syscall 23 → `sys_hello` | Returns the signed sum, or `-1` on overflow. |
| `setgroup(gid)` | stub → syscall 24 → `sys_setgroup` → `ksetgroup` | Group 0 may enter a configured nonzero group; a workload cannot leave its group. |
| `setbudget(gid,max,refill,mode)` | stub → syscall 25 → `sys_setbudget` → `ksetbudget` | Group-0 caller may configure a slot once per boot. |
| `budgetstat(gid,out)` | stub → syscall 26 → `sys_budgetstat` → `kbudgetstat` | Any process may read a coherent snapshot of a valid gid. |

The stubs are generated by `user/usys.pl`; dispatch is in `kernel/syscall.c`.
Arguments use this tree's `void argint/argaddr` helpers. `budgetstat` bounds
checks the destination against process size, copies values under the group
lock into a local structure, releases the lock, then calls this tree's
`copyout(pagetable, process_size, dst, src, len)`. It exposes no kernel pointer.

The trust model is intentionally small. Group 0 is the administrator, and
`setbudget` refuses other callers. Group configuration is atomic under the
slot lock and cannot be repeated, including by group 0. `setgroup` validates
the gid, permits naming the current gid, and otherwise allows only a group-0
process to enter an already configured nonzero slot. That transition is
one-way. Invalid gid, negative maximum or refill, and modes outside FAIL=0
and BLOCK=1 return `-1`; maximum and refill may be zero. Group 0 has a budget
and no exemption in the charge function.

`user/init.c` configures group 0 as **10000 max, 1000 per 100 ticks, BLOCK** and
group 1 as **1000 max, 100 per 100 ticks, FAIL**, before console creation and
the first shell. `init` checks both calls and does not repeat them when it
restarts the shell. The shell remains in group 0. Its `budget` built-in
configures an unused nonzero slot; `group` stores the selected nonzero gid in
shell state. Ordinary command children call `setgroup` before parsing,
redirection, nested forks, or exec. Pipelines, background jobs, lists, and
parenthesized commands inherit that gid. If assignment fails, the child exits
without running the command. A direct workload call to `setbudget` still fails
in the kernel.

## Approved policy and actual enforcement

`n` is the positive requested byte count of **one** write syscall. An admitted
positive-cost call is charged once before its first irreversible effect. The
charge is retained after a later failure or partial file write; there are no
refunds. Zero-cost operations do not change counters. The kernel currently
charges every positive-cost row below.

| Operation | Approved cost | Unit and condition | Status |
| --- | ---: | --- | --- |
| `unlink` | 12 | Per validated deletion call | **Enforced** |
| Console write | `2 + ceil(n/128)` | Per call, `n > 0` | **Enforced** |
| Same creator-group regular-file write | `2 + ceil(n/1024)` | Per call, `n > 0` | **Enforced** |
| Cross creator-group regular-file write | `6 + 2 × ceil(n/1024)` | Per call, `n > 0` | **Enforced** |
| `open(O_CREATE)` | 4 | Per call | **Enforced** |
| `open(O_TRUNC)` | 10 | Per call | **Enforced** |
| `open(O_CREATE\|O_TRUNC)` | 14 | One additive charge for both flags | **Enforced** |
| `mkdir`, `mknod` | 6 | Per call | **Enforced** |
| `link` | 3 | Per call | **Enforced** |
| User `exec` | 4 | Per call, independent of creator gid | **Enforced** |
| Unlisted operations | 0 | No charge under this policy | Current/default |

`sys_open` follows `create()` when `O_CREATE` is set and also calls `itrunc()`
for a regular inode when `O_TRUNC` is set. Both flags cost **14** together.
`sys_open`, `sys_mkdir`, `sys_mknod`, and `sys_link` copy their user path
arguments before charging, then charge outside filesystem locks and the log
transaction. A valid path string that later fails lookup or another filesystem
step retains the charge. `O_CREATE` costs 4 even when its target already
exists; `O_TRUNC` costs 10 when the flag is present, even if no truncation
occurs. These are per-call flag prices. A refused charge returns before any
create, truncate, directory update, or link-count update. Boot's kernel
`kexec("/init",...)` is the boot-only image load before budgets exist. User
`exec` charges after ELF and argument validation, after releasing inode and
log locks, and immediately before image commit. Refusal leaves the old image
and gid intact. `filewrite` charges console device writes before the driver;
pipe writes and other device writes are free. Group-0 output spends its own
configured budget.

`sys_unlink` copies the user path and checks the parent, target, `.`/`..`, and
nonempty-directory rules first. Missing targets and invalid directories are
not charged. It calls `group_try_charge(12)` just before the first directory
entry update. A FAIL refusal returns `-1` while the target remains. A BLOCK
wait releases inode locks and the filesystem transaction, waits for
affordability without deducting, then redoes lookup and validation. The final
retry performs the one actual deduction; another process may spend the
available points first, so retry can wait again. A failure after deduction
does not refund it.

`sys_write` rejects a bad descriptor before `filewrite`; negative sizes and
unwritable files also return before charging. For a positive regular-file
write, `filewrite` reads the immutable creator gid under the inode sleeplock,
releases it, charges the **requested** `n` once, then begins its possibly
multiple log transactions. A 4097-byte write costs 7 for the creator group
and 16 for another group. Refusal occurs before file content or offset
changes. Zero-byte writes are free. The user buffer is copied later by
`writei`, so a positive write with an invalid user pointer can be charged and
then fail; this is a current limitation of argument validation and the
no-refund rule. An invalid fd or negative length is rejected before charge.

## Creator-group inode format

`struct dinode` and its in-memory `struct inode` both contain `creator_gid`.
The disk inode grew from **64 to 68 bytes**, changing inodes per 1024-byte
block from **16 to 15**. `kernel/fs.h` asserts the 68-byte layout;
`mkfs/mkfs.c` checks `IPB==15` and writes creator gid 0 for boot files.
`ialloc()` clears the entire reused disk inode and stores the creating
process's gid. `ilock()` loads it; `iupdate()` persists it. The inode retains
its original creator when another group opens or writes it. The filesystem
magic is now `0x10203041`, so an old-format image must be rebuilt with this
kernel and `mkfs`; do not mount it as if the layout were unchanged. Use the
scratch-image tests below for repeatable runs. Back up any irreplaceable
`fs.img` before intentionally rebuilding it for a manual demo.

## Accounting, refill, BLOCK, and locks

`group_charge(cost)` validates the caller's gid and nonnegative cost. Zero
succeeds even for an unconfigured slot; a positive cost against such a slot
fails. Every positive deduction occurs under the group's lock, so forked
members and concurrent CPUs cannot spend the same units twice. The invariant
is `0 <= remaining <= max`; counters saturate at `UINT64_MAX` rather than
wrapping. In FAIL mode, insufficient points return `-1` immediately. In BLOCK
mode, a cost above maximum or a depleted group with zero refill also returns
`-1`; a killed waiter is refused. `group_wait_affordable` only waits and does
not reserve or deduct points.

`setbudget` sets `last_refill` to the current `ticks`. On a charge, the kernel
uses full elapsed 100-tick periods, advances `last_refill` by those periods,
keeps the partial period, and clamps the new balance at maximum. It uses a
division check against available room before multiplication, avoiding refill
overflow. The unsigned 32-bit tick subtraction covers one wrap between
charges, not multiple complete wraps. `budgetstat` reports the **stored**
balance and does not trigger lazy refill; a snapshot taken after 100 idle
ticks can therefore still show the earlier balance until a charge occurs.

The charge path takes `tickslock` before the target group lock. The timer's
`clockintr()` increments `ticks` and wakes `&ticks` waiters under `tickslock`.
For BLOCK, the caller checks the balance while holding `tickslock`, registers
with `sleep_prepare(&ticks)`, releases spinlocks, then calls this tree's
zero-argument `sleep()`. Registration remains visible even if wakeup arrives
before `sleep()`, preventing a lost wakeup. Every wake loops to recompute
refill, recheck affordability and kill state, and deduct under the group lock.
No spinlock is held while sleeping. `filewrite` drops the inode lock before
calling the potentially sleeping charge path. `unlink` uses the nonsleeping
`group_try_charge` while holding inode locks and a log transaction, then drops
them before any BLOCK wait; no group-charge path acquires an inode lock in the
opposite direction. Snapshot copyout also occurs after dropping the group
lock. This is the lock order used by these paths, not a claim that all future
filesystem hooks are safe without their own audit.

`budgetstat` returns `gid`, `configured`, `remaining`, `max`, refill rate,
mode, `n_allowed`, `n_blocked`, and `n_refused`. The first counter counts
successful positive deductions, including an operation that later fails.
`n_blocked` counts **wait registrations**, not distinct calls: a waiter can
wake and register again on each timer tick. `n_refused` counts terminal charge
refusals, including killed waiters; syscall arguments rejected before the
charge path are not counted. `user/budgetstat.c` displays all 16 groups.

## Deterministic agent boundary

There is no LLM or arbitrary shell-command execution. The Python validator
accepts a strict JSON envelope (`request_id`, `tool`, `arguments`), rejects
duplicate/unknown fields, invalid types, absolute or parent-traversal paths,
components longer than xv6's 14-character directory limit, oversized data,
and nonallowlisted program names. All six allowlisted tools run end to end.
`execute_program` permits only `hello`, `ls`, and `budgetstat`. `write_file`
accepts at most 4096 UTF-8 bytes and opens with create and truncate flags,
so it pays 14 for open plus the creator-aware write cost for nonempty data.
A later write failure can leave a truncated or partially written file.

`QemuBridge` owns a QEMU serial session, serializes requests, and sends one
bounded `relay agentop TOKEN TOOL ARG` command per validated operation. The xv6
helper changes to `/`, validates again, performs one operation, and emits
`UB1|TOKEN|...` records with hex-encoded data plus an `END|OK` or
`END|ERR|code`. The bridge ignores command echo and unrelated text, requires
the matching token and terminal record, and waits for the shell prompt before
another request. The executor verifies response shape and parses directory,
file, program output, or budget data before returning `verified_guest=True`.
For `write_file`, READY/ACK records pace bounded hex data sent over serial;
file content never enters a shell command. The trusted group-0 relay pays
console costs for framed output while the helper stays in the selected
workload group. A timeout,
broken pipe, bad frame, or unexpected QEMU exit does **not** become success.
An active serial timeout invalidates the session because the effect may be
unknown; a queued request that times out before being sent leaves the active
session usable.
The guest's `unlink` returns only `-1`, so
`unlink_failed_budget_possible` is deliberately ambiguous without a separate
budget snapshot and file-state check. The end-to-end test performs both.

## Reproduce and interpret evidence

From the repository root:

```sh
make -j2
make -j2 fs.img                 # Builds user programs and the image if needed
python3 -m unittest discover -s tests -p 'test_agent_*.py' -q
python3 tests/regression.py     # Scratch images, CPUS=1 and CPUS=3
python3 experiments/collect.py --cpus 1 3 --output /tmp/undobudget-demo-data
python3 experiments/plot.py /tmp/undobudget-demo-data
```

`kernel/param.h` sets `FSSIZE=4000`: the added guest programs left too few
free blocks in a 2000-block image for xv6's `writebig` regression. The
scratch-image harnesses build 4000-block images; an existing repository
`fs.img` is not resized in place. Back it up before choosing to rebuild it.

`tests/regression.py` runs boot authorization, fork/exec inheritance,
FAIL/shared/racing deductions, write ownership, refill, snapshots, BLOCK
waiters, creator persistence/reuse, `usertests -q`, and agent end-to-end cases
on separate scratch images. The administrator branch runs through
`tests/admin_boot.py`, which changes only a copied `init` for one boot. Its
JSON report path and per-suite PASS/FAIL are
printed; a timeout is a failure. The host charge test checks exact refill
boundaries and overflow. `tests/agent_budget_e2e.py` emits a JSON request
trace with original JSON, validated arguments, guest operation, kernel result,
budget snapshot, elapsed time, and agent-visible result. `tests/agent_smoke.py`
checks all six allowlisted tools. `experiments/collect.py` retains raw serial
logs and CSV observations, and the plotter reads only PASS runs. See
[`demo.md`](demo.md) for a short live sequence and
[`budget-tests.md`](budget-tests.md) for focused FAIL commands.

On **2026-11-10**, `tests/regression.py` completed with **32 PASS, 0 FAIL,
0 UNTESTED** on CPU counts 1 and 3; the report was
`/tmp/undobudget-regression-5t6on_23.json`. The administrator-mode test ran
through the disposable boot harness. `experiments/collect.py` completed **10 PASS, 0 FAIL**
across five scenarios and two CPU counts, with **134** guest observations.
The CSV, raw serial logs, and four SVG figures are under
`/tmp/undobudget-evaluation-complete/`. These `/tmp` paths are temporary;
rerun the commands above to reproduce the evidence. In a disposable copy,
the CI-style full `./test-xv6.py usertests` printed `ALL TESTS PASSED`, and
`./test-xv6.py crash` passed log and orphan recovery.

The known scope limits are material: Unix user identities, filesystem
permissions, and protection for administrator binaries are absent. The
group-0 shell and its operator are trusted; a deliberately run group-0
program has administrator authority. A workload able to modify trusted
executables may undermine that trust boundary. Group slots are never reclaimed
and one-time configurations require a new boot to change. Snapshot readings
are coherent per group but do not atomically combine multiple groups or a
separate uptime reading.
